# Drop Neo4j (and pika) from EnvManager

**Date:** 2026-07-30 · **Status:** accepted

## Decision

Remove Neo4j from EnvManager's dependencies, dev compose stack, configuration and
architecture documentation. Remove `pika` at the same time. PostgreSQL remains the single
store for topology.

## Why

Neo4j was in the original design as the graph store for infrastructure topology and impact
analysis, and it was provisioned early: a `neo4j:5-community` container in dev compose, a
shared instance on macmini for prod, a `NEO4J_URI`/`USER`/`PASSWORD` settings block, a pinned
`neo4j==5.16.0` driver, and a documented namespacing scheme for sharing the Community Edition
single database.

None of it was ever used. As of 2026-07-30 no backend module imports the driver —
`app/core/config.py` was the only file naming Neo4j at all. Meanwhile topology shipped for
real, in PostgreSQL: `topology_service.py`, `dependency_service.py`, the `system_dependency` /
`component_dependency` tables, and the whole `<TopologyCanvas>` / ELK front end (PRs #3–#10).
The graph store was designed for a problem that got solved another way.

`pika` (RabbitMQ client) is the same story — superseded by NATS/JetStream and never imported.

Carrying them cost real things:

- The architecture docs asserted a component that does not exist, so anyone reading them to
  plan Phase 6 would design against a store the code has never touched.
- Prod depended on a shared macmini service for nothing.
- A dev container consumed memory and required a healthcheck.
- Two unused packages sat in the dependency audit surface.

Provisioning ahead of need is cheap to undo and expensive to leave: a wrong architecture claim
misleads every future reader, whereas re-adding a dependency is a one-line change.

## Consequences

- **Phase 6 (Infrastructure Topology) plans against PostgreSQL.** Its objectives no longer
  include a Neo4j graph. If a specific traversal turns out to be impractical in SQL —
  variable-depth impact analysis is the likely candidate — reintroduce Neo4j *then*, driven by
  that query, and revisit this decision.
- Existing topology behaviour is unaffected: nothing read from or wrote to Neo4j.
- The macmini Neo4j instance is a **shared host service** used by other projects. It stays
  running; EnvManager simply no longer connects to it. See the macmini host map kept outside this repo (`envmgr-infra-notes/macmini-host-map.md`), which
  documents the host and is deliberately unchanged.

## Reinstating

`git revert` the removal commit, or re-add `neo4j` to `backend/pyproject.toml`, the compose
service, and the `NEO4J_*` settings block. The namespacing scheme previously documented for
the shared Community Edition instance (dedicated node labels per tenant) is preserved in this
file's git history.
