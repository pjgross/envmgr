# Frontend IA PR 4 — Tables Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every grid in the app renders through one component — `components/DataTable.tsx` — with saved column visibility, a consistent empty state, a reachable column picker, and two mechanical guards that stop the divergence coming back.

**Architecture:** `DataTable` already exists and is a pass-through wrapper over MUI's `DataGrid` (`Omit<DataGridProps, columnVisibilityModel | onColumnVisibilityModelChange | slots | slotProps>` plus `storageKey`, `userId`, `emptyMessage`, `showToolbar`). 28 files still render a raw `<DataGrid>` (30 instances — `MembersTab.tsx` has three). This PR hardens the wrapper in two small ways it needs before it can absorb the three hand-rolled pages, migrates all 28 files, then locks the rule in with an ESLint `no-restricted-imports` rule and a `storageKey`-uniqueness sweep test. Two smaller items from `docs/ui-audit.md` ride along because they live in the same files: P2-2 (three list pages never render their slice error) and the grid half of A1 (icon-only row actions with no accessible name).

**Tech Stack:** React 18, TypeScript (strict), MUI v7 + `@mui/x-data-grid`, Redux Toolkit, Vitest + Testing Library, ESLint 8 (`.eslintrc.cjs`, eslintrc format — **not** flat config).

**Spec:** [docs/superpowers/specs/2026-09-02-frontend-ia-and-shell-design.md](../specs/2026-09-02-frontend-ia-and-shell-design.md) §7 (PR 4 in §8's sequencing table).

## Global Constraints

- **Working directory for every command in this plan is `frontend/`.** Paths in
  **Files:** blocks are relative to the repository root.
- **The frontend suite runs WHOLE, never targeted files.** `npm test -- --run`.
  A regression on this programme survived six verification steps because every
  one of them ran a targeted file. A task is not done until the whole suite is
  green.
- **Three checks, every task:** `npm run lint` (`--max-warnings 0`, so a warning
  fails), `npm run build` (this is `tsc && vite build` — the only type check),
  and `npm test -- --run`. This PR touches no backend code, so the SQLite and
  PostgreSQL legs are not in scope; that is the one time in this repository
  "three runs" does not mean SQLite + PostgreSQL + frontend.
- **Never import `DataGrid` outside `components/DataTable.tsx`.** Type imports
  from `@mui/x-data-grid` (`GridColDef`, `GridRowParams`,
  `GridColumnVisibilityModel`, `GridValidRowModel`, …) stay legal and are used
  everywhere — the rule restricts the `DataGrid` **binding**, not the module.
- **Every `storageKey` is unique across `src/`.** Task 2 makes this mechanical.
- **`showToolbar` is left at its default (`true`) on every migrated grid.**
  Decided by the owner on 2026-09-05: none of the 28 renders a toolbar today, so
  a user who hides a column through the header menu can never restore it. The
  toolbar is what makes the persisted `storageKey` usable at all. `DataTable`
  already suppresses the Filters panel and both export buttons in server mode,
  so a server-paged grid gains Columns + Density only.
- **Preserve every existing prop when migrating.** In particular
  `disableColumnFilter` on a **client-mode** grid is NOT redundant:
  `DataTable` defaults it on only when `paginationMode === 'server'`, and
  `Projects`, `EnvironmentGroups` and `UserGroups` are client-mode grids over a
  capped fetch that set it deliberately. Keep the prop **and its comment**.
- **Copy rules:** an `emptyMessage` is a full sentence naming the entity and
  ending in a full stop. It never says "No rows". For a filtered list page it
  says "match these filters" so an empty grid does not read as an empty estate.
- **`aria-label` text matches the `Tooltip` title.** A `Tooltip` sets
  `aria-describedby`, never an accessible *name* (ui-audit A1).
- Commit per task, conventional-commit prefix (`feat:`, `fix:`, `refactor:`,
  `test:`, `docs:`). Branch: `feature/ia-tables`.

### Task 1: `DataTable` — re-read on key change, and a pruning hook

`DataTable` reads `localStorage` once, in a `useState` initialiser. If `userId`
arrives after mount — which is exactly what happens on a page whose `user` comes
from an async auth fetch — `fullKey` changes and the saved model is never
loaded. This is the *re-render, don't just mount* class that shipped three times
on Programme A.

Second, `EnvironmentList.loadColumnModel` **prunes** stored entries whose column
no longer exists (keeping any `cf_`-prefixed custom-field key regardless, because
definitions load asynchronously). `DataTable` has no such hook, so migrating that
page in Task 7 would silently drop the pruning and its tests. Add the seam here,
in the wrapper, rather than special-casing the page.

**Files:**
- Modify: `frontend/src/components/DataTable.tsx`
- Test: `frontend/src/components/__tests__/dataTableServerMode.test.tsx`

**Interfaces:**
- Produces: `DataTableProps.pruneStoredVisibility?: (stored: GridColumnVisibilityModel) => GridColumnVisibilityModel` — applied to whatever was read from `localStorage`, before it becomes state. Not applied on save. Task 7 consumes it.
- Produces: the invariant that changing `storageKey` or `userId` re-reads storage.

- [ ] **Step 1: Write the failing tests**

Append to `frontend/src/components/__tests__/dataTableServerMode.test.tsx`:

```tsx
describe('persisted column visibility', () => {
  beforeEach(() => localStorage.clear());

  it('re-reads storage when the key changes after mount', () => {
    // The saved model for user 7. A page whose `user` arrives from an async
    // auth fetch mounts with userId undefined and re-renders with 7; reading
    // storage only in the useState initialiser loses the preference silently.
    localStorage.setItem('grid-7', JSON.stringify({ b: false }));
    const columns = [
      { field: 'a', headerName: 'A' },
      { field: 'b', headerName: 'B' },
    ];
    const rows = [{ id: 1, a: 'one', b: 'two' }];

    // `disableVirtualization` is load-bearing, not decoration: the real
    // DataGrid virtualizes columns by container width and jsdom reports zero
    // width, so column `b`'s cells might never mount at all — and this test
    // would then pass for the wrong reason, asserting the absence of
    // something that was never rendered. It passes through `{...rest}`.
    const { rerender } = render(
      <DataTable
        storageKey="grid"
        rows={rows}
        columns={columns}
        showToolbar={false}
        disableVirtualization
      />
    );
    expect(screen.getByText('two')).toBeInTheDocument();

    rerender(
      <DataTable
        storageKey="grid"
        userId={7}
        rows={rows}
        columns={columns}
        showToolbar={false}
        disableVirtualization
      />
    );
    expect(screen.queryByText('two')).not.toBeInTheDocument();
    expect(screen.getByText('one')).toBeInTheDocument();
  });

  it('applies pruneStoredVisibility to what it reads, and only to that', () => {
    localStorage.setItem('grid-prune', JSON.stringify({ a: false, gone: false }));
    const columns = [{ field: 'a', headerName: 'A' }];
    const rows = [{ id: 1, a: 'one' }];
    const prune = vi.fn((stored: Record<string, boolean>) =>
      Object.fromEntries(Object.entries(stored).filter(([f]) => f === 'a'))
    );

    render(
      <DataTable
        storageKey="grid-prune"
        rows={rows}
        columns={columns}
        showToolbar={false}
        disableVirtualization
        pruneStoredVisibility={prune}
      />
    );

    expect(prune).toHaveBeenCalledWith({ a: false, gone: false });
    // `a` was hidden by a real stored preference and survives pruning.
    expect(screen.queryByText('one')).not.toBeInTheDocument();
  });
});
```

The file already imports `render`, `screen`, `DataTable`, and vitest globals —
check the header and add only what is missing (`vi` may already be imported).

- [ ] **Step 3: Implement**

In `frontend/src/components/DataTable.tsx`, add the prop to the type:

```tsx
  /** Set true to render the DataGrid toolbar (density toggle, columns, export, filters). */
  showToolbar?: boolean;
  /**
   * Applied to the model read from localStorage, before it becomes state —
   * never to what is saved. A page whose columns are partly tenant-defined
   * uses this to drop entries naming a column that no longer exists, while
   * keeping namespaced custom-field keys whose definitions may not have
   * loaded yet. See EnvironmentList.
   */
  pruneStoredVisibility?: (stored: GridColumnVisibilityModel) => GridColumnVisibilityModel;
```

Destructure it in the signature (`pruneStoredVisibility,` next to `showToolbar`),
and replace the `useState` initialiser with a state + effect pair:

```tsx
  const [columnVisibilityModel, setColumnVisibilityModel] = useState<GridColumnVisibilityModel>(
    () => {
      const stored = loadVisibility(fullKey);
      return pruneStoredVisibility ? pruneStoredVisibility(stored) : stored;
    }
  );

  // `fullKey` changes when `userId` resolves — a page whose user comes from an
  // async auth fetch mounts with it undefined. Reading storage only in the
  // initialiser above would drop that user's saved preference on the floor,
  // silently, on every such page. `pruneStoredVisibility` is deliberately not
  // in the dependency list: an inline arrow prop is a new identity every
  // render, which would re-read storage on every render and clobber an
  // in-session toggle.
  // eslint-disable-next-line react-hooks/exhaustive-deps
  useEffect(() => {
    const stored = loadVisibility(fullKey);
    setColumnVisibilityModel(pruneStoredVisibility ? pruneStoredVisibility(stored) : stored);
  }, [fullKey]);
```

Add `useEffect` to the `react` import.

### Task 2: The `storageKey` uniqueness sweep

Two grids sharing a `storageKey` share one `localStorage` entry, so hiding a
column on one silently hides a differently-named column on the other — the same
shape as the custom-field column-id collision recorded in CLAUDE.md. It cannot
be caught by a rendered assertion (no test mounts two pages at once), so it is a
structural sweep, following `__tests__/tabMechanism.test.ts` and
`__tests__/systemSliceConsumers.test.ts`.

Write it **now**, before the migrations, so every later task is guarded as it
lands rather than audited at the end.

**Files:**
- Create: `frontend/src/__tests__/storageKeys.test.ts`

**Interfaces:**
- Consumes: nothing.
- Produces: the invariant Tasks 3–7 must not break.

- [ ] **Step 1: Write the test**

```ts
import { describe, expect, it } from 'vitest';

// `import.meta.glob` enumerates AND reads every source file, with no Node
// builtins — this package has no `@types/node`, so `fs`/`path` would fail
// `tsc --noEmit`. Same technique as systemSliceConsumers.test.ts.
const files = import.meta.glob<string>('../**/*.{ts,tsx}', {
  eager: true,
  query: '?raw',
  import: 'default',
});

/**
 * A DataTable's `storageKey` names one localStorage entry. Two grids sharing
 * one share their column-visibility model, so hiding a column on one silently
 * hides whatever column happens to sit at that index on the other. No rendered
 * test can see this — it needs two pages mounted at once — so it is asserted
 * on the source.
 */
describe('every storageKey is unique', () => {
  // Test files legitimately reuse throwaway keys against a cleared
  // localStorage, and the wrapper's own default lives in DataTable.tsx.
  const isProductionFile = (path: string) =>
    !path.includes('__tests__') && !path.includes('/test/') && !path.endsWith('DataTable.tsx');

  it('no two production grids declare the same storageKey literal', () => {
    const seen = new Map<string, string[]>();
    for (const [path, source] of Object.entries(files)) {
      if (!isProductionFile(path)) continue;
      for (const match of source.matchAll(/storageKey="([^"]+)"/g)) {
        const key = match[1];
        seen.set(key, [...(seen.get(key) ?? []), path]);
      }
    }
    const duplicates = [...seen.entries()].filter(([, paths]) => paths.length > 1);
    expect(duplicates, `storageKey reused: ${JSON.stringify(duplicates)}`).toEqual([]);
  });

  it('every computed storageKey is allowlisted', () => {
    // A template-literal key can't be compared for uniqueness by reading the
    // source, so each one is named here deliberately. RaidTab's key is
    // `release-raid-${typeTab}`, one entry per RAID type tab, which is the
    // point — the tabs are different grids.
    const ALLOWED_COMPUTED = new Set(['../components/releases/raid/RaidTab.tsx']);
    const computed: string[] = [];
    for (const [path, source] of Object.entries(files)) {
      if (!isProductionFile(path)) continue;
      if (/storageKey=\{/.test(source) && !ALLOWED_COMPUTED.has(path)) computed.push(path);
    }
    expect(computed, 'a computed storageKey escapes the uniqueness check').toEqual([]);
  });
});
```

// eslint-disable-next-line react-refresh/only-export-components
export function pruneStoredColumnModel(
  stored: GridColumnVisibilityModel,
  knownStaticFields: readonly string[] = STATIC_COLUMN_FIELDS()
